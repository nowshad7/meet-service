# Transcription

`MEET_FEATURES=transcription` opts a deployment into a legacy Jigasi live-caption pilot on `stable-11146-2`.
Use the source workflow (`scripts/meet`) for this pilot; the standalone `deploy/compose.yml` release workflow does not yet include it.
It activates only with a nonempty private `JIGASI_TRANSCRIBER_WHISPER_URL`.
An empty URL or an absent feature adds no transcriber or transcription overlay and leaves normal deployment behavior unchanged.

## What it does

`scripts/meet` includes the pinned upstream `transcriber.yml` and `compose/transcription.yml`, sets `ENABLE_TRANSCRIPTIONS=1` for web, Prosody and Jicofo, and selects Jigasi's bundled `WhisperTranscriptionService`.
Jicofo invites Jigasi from its brewery when an authorized participant requests captions.
Jigasi captures speaker audio and sends JSON caption messages back through the room to Jitsi's existing subtitles UI.
This uses the legacy `requestingTranscription` presence path, with no bridge transcription URL or `asyncTranscription` wiring.
Transcript files, audio recording, transcript URL advertising and translation are explicitly disabled.
Final transcript uploads and the private recognition service are outside this feature.

`mod_meet_transcription` runs after upstream token verification and fixes room entitlement from the first ordinary participant's verified token.
Both `context.features.transcription: true` and `context.room.transcription.enabled: true` are required, together with deployment opt-in.
A later token cannot enable a denied room.
The module removes transcription-request presence on joins and subsequent updates unless the room is entitled and the requesting participant has a verified token with the feature claim.
A direct hidden-transcriber invitation into a denied room is rejected too.
Focus/admin and healthcheck joins cannot establish entitlement.
Moderator status alone grants no transcription entitlement.

The default brand loads `transcription-language.js`, which is inert unless captions are enabled and the token opts in with a supported language.
After the conference joins, it announces the local speaker's `transcription_language` as `bn` or `en` using the pinned client's participant-property API.
It also applies the language to a newly initialized conference after reconnecting.
This bypasses the pinned web client's language allowlist, which otherwise rejects Bangla and falls back to English, without patching upstream files.
The browser reads the token for language selection; only Prosody decides permission from verified session claims.
Deployment brands overriding `plugin.head.html` must include this script themselves.

## Settings

| Setting | Use |
|---|---|
| `MEET_FEATURES` contains `transcription` | Opts in; activation also requires a nonempty backend URL |
| `AUTH_TYPE=jwt` | Required for the pilot's verified token permission gate |
| `JIGASI_TRANSCRIBER_WHISPER_URL` | Private Jigasi/Skynet-compatible WebSocket endpoint; empty by default |
| `JIGASI_TRANSCRIBER_WHISPER_PRIVATE_KEY`, `JIGASI_TRANSCRIBER_WHISPER_PRIVATE_KEY_NAME` | Optional private backend authentication; key stays in deployment secrets and is never generated by `init` |
| `JIGASI_XMPP_USER`, `JIGASI_XMPP_PASSWORD` | Brewery account, default user `jigasi`; password generated privately by `init` |
| `JIGASI_TRANSCRIBER_USER`, `JIGASI_TRANSCRIBER_PASSWORD` | Hidden participant account, default user `transcriber`; password generated privately by `init` |
| `JIGASI_BREWERY_MUC` | Brewery shared by Jigasi and Jicofo, default `jigasibrewery` |
| `XMPP_AUTH_DOMAIN`, `XMPP_INTERNAL_MUC_DOMAIN`, `XMPP_HIDDEN_DOMAIN` | Upstream account and brewery domains; hidden domain defaults to `hidden.meet.jitsi` |

The transcriber waits for a Prosody healthcheck confirming both accounts exist, avoiding a first-start login race.
The upstream Prosody initializer creates matching brewery and hidden participant accounts from these credentials.
Configure the URL in the private deployment's `deployment.env` and any provider key in its uncommitted `secrets.env`.
No provider key, model file, vendor endpoint or provider secret belongs in the repository or images.
The backend must implement Jigasi's streaming Whisper protocol, not a stock HTTP transcription API, and run a multilingual model supporting Bangla and English.
Keep the backend, models and audio processing self-hosted and private.

## Contract

An entitled join token includes this context:

```json
{
  "features": { "transcription": true },
  "room": { "transcription": { "enabled": true, "language": "bn" } }
}
```

Use `en` for English speakers and `bn` for Bangla speakers, one language per speaker or class.
Every participant permitted to request captions needs the feature claim; entitled speakers should carry their own language.
Start captions manually in Jitsi's subtitles UI.
Room `autoStart` and `save` options do not initiate transcription or enable saving in this pilot.
Translation is outside the pilot; do not select a translation/output language, since Jigasi's Whisper adapter can prefer it over the source language.
End-to-end encrypted audio cannot be recognized by a server transcriber.

## Tests

`tests/plugins/mod_meet_transcription_spec.lua` covers deployment and token permission, first-join room policy, start requests, updates and denied hidden-transcriber joins.
`tests/meet-test.sh` covers opt-in, empty backend behavior, private secret generation and compose-file selection.
`tests/transcription-language.test.mjs` covers Bangla/English participant properties after initialization, reconnects and inert cases.
`tests/transcription-config-check.sh` renders pinned image templates and checks the merged compose configuration, Whisper settings, matching account names and disabled transcript saving.
These checks verify wiring and simulated client/server behavior, not recognition quality or a live meeting.

Live Bangla captions have **not been tested end to end**.
Bangla accuracy, same-speaker code-switching, latency and concurrent-class capacity are unmeasured.
Evaluate real Bangladeshi classroom audio, speaker association, stop/restart, privacy rooms and poor microphones against the private backend before making any wider support promise.
